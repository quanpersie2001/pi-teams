# ADR: isolated local peer messaging

Status: authenticated Unix-domain transport and Pi host wiring implemented. Windows peer ingress uses a source-only PowerShell/.NET named-pipe helper that creates the actual pipe with `PipeOptions.CurrentUserOnly`; it fails closed if PowerShell/.NET support is unavailable. Native Windows verification remains pending.

Use a per-runtime Unix-domain socket for local ingress plus an owner-only filesystem registry/inbox/receipt store. No daemon, Herdr, tmux, or shared team secret. Discovery uses canonical `projectId` (Git common-dir for worktrees, explicit canonical root for non-Git). Runtime addresses include stable session ID and fresh runtime incarnation; old-runtime mail is never read by a new incarnation.

Sender identity uses Ed25519. Each runtime advertises its SPKI public key; ingress resolves the exact fresh sender session+runtime to that key and verifies a signed versioned message/timestamp/nonce frame before atomic acceptance. Acceptance binds an immutable full-envelope fingerprint, applies durable per-sender rate limits and aggregate quota, and atomically enqueues. It rejects unknown/stale sender keys, wrong recipient runtime, expired or >1-hour TTL frames, timestamps >60 seconds in the future, replayed nonces, malformed/oversized frames, and conflicting duplicate IDs. `PeerMessagingService.receive(envelope)` checks the durable immutable binding; callers cannot assert sender identity. Refused, expired, and delivered receipts are terminal tombstones. A `queued` response means verified durable enqueue, not model delivery. Cancellation before the inbox hard-link succeeds aborts acceptance; once that link succeeds it is the commit point, and the host records the queued receipt and joins that operation despite a concurrent abort. Shutdown may therefore make the sender's response ambiguous, but the durable inbox entry and receipt remain truthful.

On Unix, the socket parent must be current-user-owned/private and socket mode is 0600; the storage adapter rejects symlink traversal (allowing macOS /var and /tmp canonical aliases) and requires owner-only directory modes. On Windows, `LocalPeerHost` provisions a protected per-user DACL through bounded PowerShell ACL operations, after validating every existing path component against reparse points. It verifies owner/current-user SID, protected DACL, and required current-user FullControl on readback; existing descendants and files are audited without following reparse points and unsafe explicit/protected ACEs are rejected rather than rewritten. The named pipe is created and owned by `windows-peer-pipe.ps1`, launched specifically with `pwsh.exe` (PowerShell 7+) and a .NET runtime whose `PipeOptions` exposes `CurrentUserOnly`; an actual capability probe runs before launch and the helper repeats the check by enum name before pipe creation. The pipe uses `NamedPipeServerStream` with that named option, enforcing account and elevation matching at connection time. Node mediates bounded newline-framed requests over the helper's controlled stdio; it does not create or post-hoc repair the pipe. Windows PowerShell 5.1 (`powershell.exe`) remains the ACL helper runtime only and is never used as a pipe-helper fallback. Each request owns an `AbortController`; deadlines and ingress/session shutdown propagate through mailbox acceptance, quota-lock waits, and message claims, and shutdown joins the underlying operations before closing helper stdio. Missing `pwsh.exe`, PowerShell below version 7, or a runtime without the named `CurrentUserOnly` enum value fails closed with an actionable prerequisite diagnostic; no numeric enum fallback is used. Same-user/elevation-equivalent processes that can read runtime private keys or modify the private data root are outside the isolation guarantee.

Inbound policy is receiver-owned and defaults to `hold`; project settings cannot elevate it. Peer text is untrusted plain text and does not grant lifecycle/task authority or share transcript/thinking. Bounds: 16 KiB UTF-8 body, 100 pending+held messages per runtime, and 10 inbound messages per sender runtime per 10 seconds. Inbox/held transfer and ingress quota checks share an atomic filesystem lock. In-flight receive/approval uses per-message exclusive claims (5-minute stale lease; a live owner PID prevents lease stealing). Receipt states are append-only markers with terminal precedence, so queued cannot regress terminal state. Bindings/tombstones persist for seven days after envelope expiry; records are capped at 10,000 bindings and 10,000 rate identities; at most 10,000 distinct receipt IDs can be introduced between cleanup runs, with up to three transition markers per ID (30,000 marker files). Cleanup occurs on ingress (at most once per minute) and is also exposed as `LocalPeerHost.prune`; hosts should invoke prune periodically. Delivery remains at-least-once; no claim of exactly-once side effects.

Peer delivery through the wired runtime dispatches `sendUserMessage` with a unique correlation marker and only treats the matching SDK `message_start` event as acceptance. A bounded missing-ack timeout is ambiguous: pending mail is preserved, and retry may duplicate delivery; this is the documented at-least-once contract, not an exactly-once guarantee. Offline native smokes cover two independent SDK sessions, production loader registration, real busy safe-point delivery, and combined lifecycle/peer flow. The owned-PTY production TUI smoke renders held approval/refusal and busy-child shutdown. These are automated proofs, not human manual verification or broad SDK-range proof.

## Integration recipe

1. Resolve scope with `resolvePeerProjectId(cwd, explicitNonGitRoot?)`. Provision and verify private peer storage before ingress; on Windows this uses a protected current-user DACL. Do not put private keys or storage in a shared/project directory.
2. For each **main session only**, generate an Ed25519 keypair and a fresh `runtimeId`; get endpoint path from `createPeerEndpointPath(privateRoot)`. Start `startPeerIngress({ address, socketPath, resolveSenderKey: createPeerKeyResolver(host, projectId), mailbox: host })`. Windows ingress is owned by the `CurrentUserOnly` helper and fails closed if its prerequisite probe fails. Only after ingress successfully starts, publish a `PeerAdvertisement` with `identityPublicKey` as SPKI PEM and endpoint kind matching the platform.
3. Instantiate `PeerMessagingService` with `createPeerTransportSender(privateKey, resolveEndpoint)`; resolve endpoint by exact recipient session+runtime from validated registry ads. `PeerMessagingService.send` fails closed without this authenticated transport. For accepted inbox items, call `PeerMessagingService.receive(message)`; it checks the durable fingerprint/sender binding and acquires the per-message claim. Poll `LocalPeerHost.pending(localAddress)` and retain delivery failures for retry; call `host.prune()` periodically. This package does not supply a scheduler.
4. On session shutdown, stop polling, close `PeerIngress` (which removes its socket), and unregister the exact advertisement. Never reuse runtime ID, key, or endpoint on restart. Do not automatically resume closed sessions.
5. Instantiate messaging with receiver-owned immutable policy defaulting to `hold`. Surface `heldMessages()` and explicit `approveHeld(id)` / `refuseHeld(id)` actions; no held body reaches the model before approval. Use the serialized `SafePeerSdkAdapter` hook for validated idle/busy delivery.
6. Register `createPeerTools(...)` handlers as `peer_sessions`, `peer_send`, `peer_activity`; do not expose lifecycle operations. Exported APIs: `startPeerIngress`, `PeerIngress.close`, `sendPeerMessage`, `createPeerTransportSender`, `createPeerKeyResolver`, `PeerDiscoveryService`, `PeerMessagingService`, `LocalPeerHost`, `SafePeerSdkAdapter`, `resolvePeerProjectId`, `createPeerTools`; contracts `PeerAddress`, `PeerAdvertisement`, `PeerPolicy`, `PeerMessage`, `PeerReceipt`.

## Verification limits

Unix-domain ingress was exercised with a separately spawned Node child process, not a commercial provider. Authentication/send/receipt and adversarial transport cases are covered by `test/integration/peer-transport.test.ts`; host invariants are covered by peer host/messaging unit tests. Windows ACL provisioning and pwsh/.NET named-pipe capability/handshake tests are conditional and were not run on this macOS host. The helper creates the pipe with `CurrentUserOnly`; no post-listen DACL repair is used. Production loader registration, real busy safe-point delivery, combined lifecycle/peer flow, and actual rendered TUI behavior have automated smoke coverage (`native-loader-registration.test.ts`, `peer-sdk-busy-smoke.test.ts`, `lifecycle-peer-e2e.test.ts`, `actual-tui-peer-inbox.test.ts`). Native Windows proof and human manual TUI verification remain outstanding.
